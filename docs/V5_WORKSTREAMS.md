## Lead decisions (already taken)
- **Pricing/trial/seats are already implemented (V4).** V5 presents them; it does not create a second catalogue. Marketing,
  checkout, billing settings, entitlements and Platform admin read `v4-plans.ts` / the persisted plan versions. The public
  page shows exactly Standard £10 and Professional £25 per user / month, "14 days free", no card required, no tax claim.
- **Routes (D23):** marketing page at `/` (public, server-rendered, no app bundle); app home moves to `/overview`; default
  post-login return becomes `/overview`; every other route unchanged; signed-in visitors on `/` see "Open dashboard".
- **Palette (D24):** purple marketing tokens scoped to the marketing route; app keeps orange; existing Relay mark
  (`apps/web/public/brand/relay-mark.svg`).
- **UI stack (D25):** shadcn/ui (Base UI-backed variants) + Motion for React for marketing, widget and AI workspace. Check
  installed versions and current official docs first; add dependencies once (lead-approved: `motion`, Base UI, shadcn
  copy-in components + their small deps such as `class-variance-authority` if needed). Never wrap one control in two
  interactive primitives; keep existing Radix-based app components where they work.
- **Signup handoff:** the dev Keycloak realm may enable self-registration (local only, MKT) so the marketing →
  `/signup?plan=` → workspace → trial flow is testable end to end; production registration is an activation item.
- **AI without a key:** workflows run their deterministic steps for real (read sources, validate destinations, save
  drafts, query analytics, create tasks) and report "AI is not set up" for model steps; tests use a fake model provider
  injected in tests only. No fabricated AI output anywhere in the product.
