## Decisions
- H1: TikTok guidelines say interactions are off by default and the user turns them on, so the adapter's
  `allowComment !== true ⇒ disable_comment` was right and the UI was wrong (showed ON when unset). Persisted meaning of
  `allowComment` is unchanged (unset = not allowed) — no migration. A creator-locked interaction is forced off at send
  time (prepare re-reads creator_info) rather than failing the post.
- H3: alt text is read from `assets.alt_text` at send time; it is part of the approval binding (approval-policy
  computeBinding), so what is sent is what was approved. Over-limit = blocking validation issue (`alt_text_too_long`),
  consistent with V3 5.6 "no silent truncation" and the existing Pinterest option check.
- H7: connection JSON now serves the adapter's current capabilities (fallback: stored record) so a capability change
  shows without waiting for a health check; MCP and diagnostics already used the same `capabilitiesFor`.
