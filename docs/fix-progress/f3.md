## Decisions
- `AI_MODEL` has **no default**. AI is on only with the provider key (env or Setup) **and** `AI_MODEL`; the fixture
  (`AI_FIXTURE`, never in production) still needs neither. A test-injected client also needs `AI_MODEL`.
- `AI_FALLBACK_MODELS` (optional, comma list) = model ids for which Relay requests the provider's server-side refusal
  fallback. Applies to both the drafting client and the assistant client (the assistant previously always asked; now
  only for listed models, so an unlisted model never gets an unsupported request).
- `AI_MODEL_PRICES` (optional JSON `{"<model id>": [inUsdPerMTok, outUsdPerMTok]}`). No price ⇒ cost estimate `null`
  ("Unknown · prices not set"), never guessed. Admin aggregates compute cost at read time from token totals grouped by
  model × configured prices (so later price changes apply; any unpriced model with tokens ⇒ unknown). The stored
  `cost_estimate_usd` columns stay `NOT NULL` (no migration allocated): written as the estimate when priced, else 0,
  and no longer read for display. Budgets are token-based and unchanged.
- All three are environment-only (D32 "from environment"), validated at boot (zod in `config.ts`; errors name the
  variable and the rule, never the value). Setup → AI assistance lists them as Set / Not set (values never sent);
  `putSetup` refuses them with `invalid_state`. Platform → Integrations "AI assistance" lists missing
  `ANTHROPIC_API_KEY` / `AI_MODEL` and notes a missing price.
